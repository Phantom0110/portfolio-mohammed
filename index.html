Lock-Free Concurrent Queue — Breakdown

An implementation of the Michael-Scott non-blocking queue (PODC '96) in C++17, built to understand what "lock-free" actually buys you and what it costs.

What I built

  • Enqueue/dequeue with std::atomic CAS loops, plus the "helping" step that lets threads advance a lagging tail
  • Acquire/release memory ordering instead of blanket seq_cst, avoiding unnecessary fences
  • head_ and tail_ padded onto separate 64-byte cache lines to eliminate false sharing
  • A bump-allocated node pool that sidesteps the ABA / use-after-free hazard without an unsafe delete
  • Concurrent correctness tests: FIFO ordering, empty-queue semantics, 8-thread producer races, interleaved workloads

The honest result

I benchmarked it against a mutex queue across three scenarios (up to 8 threads, 1.6M operations), and the mutex version won on raw throughput on Windows. The README explains why: CAS contention, scheduler behavior, and allocator serialization. It also covers where lock-free structures really win: bounded tail latency and immunity to deadlock.
